# RECORDING.md — 作業記録の書き方（全プロジェクト共通・2026-09-15 新設）

> **毎回は読まない。work-log や指示の原文を書く時にだけ開く。**
> 「いつ書くか」の短い決まりは `COMMON.md` の「■ 作業の記録」にある。ここはその詳しい版。
> 作った理由（拓巳の依頼 2026-09-15、2026-09-22 全AI全文保存へ拡張）＝あとから作業を完全に振り返れて、記事・手順書・教材にそのまま使える材料を残すため。
> **全文ログ＝一次資料、work-log＝検索用の索引。両方を残す。要約だけ残って、実際の会話・指示・設定・判断理由が消える状態を一番避ける。**

## 1. どこに何があるか（3層）

| 層 | 中身 | 置き場所 | 毎回読むか |
|---|---|---|---|
| 1. 共通 | 記録の決まり | `~/ai-rules/COMMON.md`（短い決まり）／このファイル（詳しい書き方） | COMMONだけ毎回 |
| 2. プロジェクト固有 | その案件で**追加で**残す項目 | 各リポジトリの `AGENTS.md` の「作業の記録（固有の項目）」節 | 毎回（短く保つ） |
| 3. 実際の記録 | 作業ごとの要約・索引 | `work-log/YYYY-MM-DD_プロジェクト名_題.md` | **直近2件だけ** |
| 3. 指示の原文 | 再利用したい重要な指示・プロンプト | `work-log/prompts/YYYY-MM-DD_何の指示か.md` | 読まない（必要な時だけ） |
| 3. 会話の全文 | Claude Code / Codex / ChatGPT の会話・判断過程・道具の実行と結果 | `brain/90_System/transcripts/<provider>/<project>/...md`。GitHubには秘密情報を伏せたMarkdownだけ置く | 読まない（必要な時だけwork-logから辿る） |
| 3. 生の会話記録 | 各AIが元々持つ機械向けログ | Claude Code=`~/.claude/projects/.../*.jsonl`、Codex/ChatGPTは各ソース。GitHubへそのまま置かない | 保険。取り込み時だけ読む |
| 3. スマホ・Webの会話の写し | クラウドで消える前の会話全文（2026-09-23〜） | 各リポジトリの `記録/会話/cloud/<日付>_<会話ID>.jsonl`。**秘密を伏せてから**置く（下の§5） | 読まない。PCの取り込み機が brain へ変換する |
| 3. 前後の記録 | 「こう変えたら、こうなった」＝前と後の組（画像・文章）と、どうなったか | 各リポジトリの `記録/前後/YYYY-MM-DD.md`（並べた絵は `見本/前後/` か `記録/前後/画像/`）。下の§10 | 記事・教材を作る時に読む。未記入の★は作業の区切りで埋める |

「今どこまで進んだか・何が決まったか」は、記録とは別に既存の置き場所がある。**記録に写さない**（二重になる）：
決定＝各リポジトリの `docs/決まったこと.md`（あれば）／やること＝`post-creator/tasks/tasks.json`（台帳）／好み・注意＝Claude Code の自動メモリ。

## 2. いつ書くか

**意味のある区切りが来たら、その場で当日の work-log に追記する。最後にまとめて書かない。**
（長い会話は途中で圧縮されて細部が消える。圧縮の後に思い出して書くと、指示や試行が抜ける）

区切り＝調査が一区切りした／重要な判断をした・拓巳が決めた／重要な指示・プロンプトを使った・変えた／
成果物を作った／重要なコードや自動化を作った／失敗した・想定と違った／問題を解決した／
方針・設定を変えた／数字や結果を取った。

**書かないもの**：誤字直し・ファイルを見ただけ・一時的な確認・成果につながらなかった細かい操作。
判定＝「半年後に、なぜ今こうなっているのかを理解するのに要るか」。要らないなら書かない。

- **work-log を書いた区切りでは、その記録と同じ作業の変更だけをコミットして、そのまま push まで行う。** 拓巳への都度確認は不要。無関係な未コミット変更は含めない。push 先は各リポジトリの決まりに従い、失敗した時だけ止めて理由を報告する（2026-09-26・全セッション共通）

- 全文ログは要約せず一次資料として残し、work-logには「何を・なぜ・結果・どこを見れば原文があるか」を書く。全文の代わりにwork-logへ会話を丸写ししない
- 1日に作業が複数あれば、題ごとにファイルを分けてよい（同じ作業なら同じファイルに追記）
- 圧縮の後は、推測で埋めない。`python ~/ai-rules/tools/transcript.py show <会話ID> --tools` で原文を確かめて書く

## 3. work-log の形

> 2026-09-28以降、この形式は全セッション・全リポジトリ共通。Claude Code / Codex / ChatGPT / その他のAIから書く場合も同じ形式を使う。work-logを書く直前にこの§3を確認する。
> Claude Code/Codex側のフックに加え、GitHub側でも同じ必須項目を検査する。AIがこのファイルを読み忘れても、形式違反を機械で検出できる状態を正とする。

欄の順番は固定。**全項目を毎回必ず書く。見出しを省略しない。** 該当しない場合は `なし`、確認できない場合は `未確認` / `取得できず` と書く。数字は推測で埋めない。

```
---
date: YYYY-MM-DD
project: プロジェクト名
実行モデル: 作業を動かしたモデル名（例：Claude Opus 5 / Codex GPT-5.6 / ChatGPT GPT-5.6）
provider: claude-code / codex / chatgpt / other
session: 元AIの会話ID・セッションID（取れない場合だけ空）
transcript: brain/90_System/transcripts/... の全文ログへの相対パス（まだ取り込めていなければ 未取込）
（プロジェクト固有の欄があればここに足す。例：段階:）
---
## 作業内容
- 目的：今回やろうとしたこと
- 前提・仮説：なぜやったか／どうなると予想していたか
- やったこと：後から読んで何を実行したか分かる具体さで（「調査した」で終わらせない。何を・どこで・どう）
- 結果：何ができた・何が分かった（成果物はパスを書く）
- 進捗：作業開始前→今回到達した状態（例：調査中→実装済・検証待ち、検証中→完了、未解決なら保留）。各案件で呼び方は変えてよいが、何が進んだか具体的に書く

## 使った指示・道具
- 道具：使ったAI・ツール・外部サービス（重要なら モデル名・版・設定も）
- 指示：短いものはそのまま引用。長いものは原文ファイルのパス（→ 4.）

## 試したこと（失敗→修正）
| 回 | 何を変えたか（指示・設定・コード） | 結果 | 成果物 |
|---|---|---|---|
| なしの場合 | なし | なし | なし |

## 前後比較
- Before：作業前の状態・症状・数値・画面・ログなど
- After：作業後の状態・結果・数値・画面・ログなど
- 証拠：ログ・コマンド結果・画像・ファイル・コミット等、あとで比較を再確認できる場所
- 本当に比較対象がない調査・相談・アイデア記録だけは `比較不要：理由` と書く

## 決定事項
- 採用したもの：〜　理由：〜（**「なぜ」を必ず書く**。見送った案があれば、なぜ見送ったかも）

## 数字
- 項目：値（出どころ・取った日）。測れていない場合は `未確認` / `取得できず`。**推測で埋めない**

## 素材（あとで記事・教材にできそうなもの）
- 例：初心者が詰まる所／意外だった所／失敗談／Before→After／そのまま使えるプロンプト／テンプレ・手順・自動化にできる所
- 無ければ `なし`。判断できなければ `未確認`。

## 変更ファイル

## 未解決事項

## 次のアクション
- セッションが変わっても、ここを読めば次の一手が分かる書き方にする
```

- **変更・修正・設定・自動化・導入・不具合解決・生成物の改善など、作業前後で状態が変わるものは `## 前後比較` を必ず実データで書く。** 「比較不要」にはしない。コードはコミット番号、画像はファイルのパス、文章は前後を引用、設定や不具合はログ・コマンド結果・画面状態を残す
- 調査・相談・アイデア記録など、実際に状態を変えていない作業だけ `比較不要：理由` を許可する
- 目的は「あとで記事化する時に、何がどう良くなったかをその場の記憶なしで比較できること」。Afterだけ、感想だけ、「成功した」だけでは不足
- 決定が変わったら、`docs/決まったこと.md`（あるプロジェクトのみ）も直す。work-log は「その日の記録」、決まったこと.md は「今の決定」

## 4. 指示・プロンプトの残し方（最重要）

後から「何て指示したんだっけ？」に必ず答えられる状態にする。**整えない・要約しない・言い換えない。そのまま残す。**

| どんな指示か | 残し方 |
|---|---|
| 短い（数行） | work-log の「使った指示」にそのまま引用 |
| 長い（拓巳の依頼文・別のAIに渡した長文） | 全文ログに残るので原則二重保存しない。**そのまま再利用したい指示**だけ `work-log/prompts/` に抜き出す |
| 拓巳が会話に打った長い依頼 | 全文ログを正本にする。再利用用に独立保存したい時だけ、Claude Codeなら `python ~/ai-rules/tools/transcript.py save <会話ID> <番号> work-log/prompts/YYYY-MM-DD_題.md` を使う |
| リポジトリの中のファイルになっている指示（テンプレ等） | 写さない。パス＋コミット番号を書く（git が全部の版を持っている） |
| ファイルの指示を書き換えながら何度も試す | **上書きで前の版を消さない。** 試す前にその版をコミットするか、`prompts/` に `_v1` `_v2`… で写す。どの版で何が起きたかは「試したこと」の表に書く |
| 別のAI（ChatGPT・画像生成AI等）で使った指示と設定 | 会話全文を正本にする。再利用価値が高い指示だけ `prompts/` に原文＋設定を抜き出す。結果の画像や文章はパスで指す |

原文ファイルの頭には次を書く：
```
---
date: YYYY-MM-DD
種類: 拓巳の指示 / 別のAIへの指示 / 画像生成の呪文 など
使った先: どのAI・道具（モデル・設定）
結果: 採用 / 不採用 / 途中の版（→ どの work-log か）
---
## 原文
（そのまま）
```

会話全文は provider 共通で `brain/90_System/transcripts/` に集約する。Claude Codeの生ログは引き続き `transcript.py` でも検索できる。Codex / ChatGPT の取り込み機が未実装・失敗中の時は、work-log の `transcript: 未取込` を残し、取り込めたふりをしない。

## 5. 会話全文の残し方（一次資料）

### 保存先

GitHub上の正規化済み全文ログは、brain に集約する。

```
brain/90_System/transcripts/
├─ claude-code/<project>/YYYY-MM-DD_<session>_<題>.md
├─ codex/<project>/YYYY-MM-DD_<session>_<題>.md
└─ chatgpt/<project>/YYYY-MM-DD_<session>_<題>.md
```

- 原本のJSONL・エクスポートZIP等はPC側に残してよいが、そのままGitHubへ置かない
- GitHubへ保存する前に、APIキー・トークン・Cookie・メール等を伏せる
- 画像・音声・添付ファイルはバイナリを全文ログへ埋め込まず、取得できるファイル名・ID・元パス等を参照として残す
- 元AIから取得できる範囲で、**ユーザー発言・AI回答・道具の呼び出し・道具の結果・時刻**を順番どおり残す。取得できない項目を推測で補わない
- 全文ログは文章を整えない。記事向けの編集・要約はwork-logや別の成果物で行う

### 全文ログの先頭

```
---
date: YYYY-MM-DD
provider: claude-code / codex / chatgpt
project: プロジェクト名
session: 元の会話ID
source: 元ログの種類・場所（秘密値は書かない）
work_log: 対応するwork-logのパス（無ければなし）
---
```

### providerごとの原本

- Claude Code：`~/.claude/projects/.../<会話ID>.jsonl`（＋`<会話ID>/subagents/*.jsonl`）を原本とする。保存期間3650日の設定は維持
- Codex：`~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` と `~/.codex/archived_sessions/rollout-*.jsonl`（2026-09-22 実機で確認・46件）。題名は `~/.codex/session_index.jsonl`
- **スマホ・Web版の Claude Code（2026-09-23〜）**：原本はクラウドの使い捨てのパソコンにあり、セッションが片づくと消える
  （/teleport でPCへ移した会話しか残っていなかった）。そこで `tools/save_transcript.py`（Stop フック・クラウドだけ）が
  返事のたびに `記録/会話/cloud/<日付>_<会話ID>.jsonl` へ写して push する。**上の「生のログはGitHubへそのまま置かない」の例外**：
  置かないと消えるため。代わりに `secret_mask.py` で1行ずつ伏せてから置く（2026-09-23 拓巳「全文取り込めるようにして」）。
  PCに降りてきたら `archive_transcripts.py` が拾って brain の Markdown にする（PCに同じ会話があればPCの方を使う）
- ChatGPT：公式データエクスポートを原本として取り込む。**2026-09-22 時点で実ファイルが無く、変換は未実装**（`chatgpt --input` は中身の一覧を見せるだけ）。エクスポートが手に入ったら形を見てから足す

### 取り込み機（2026-09-22）

`python ~/ai-rules/tools/archive_transcripts.py` が上の原本を Markdown にして `brain/90_System/transcripts/` へ置く。

| やりたいこと | コマンド |
|---|---|
| 今の会話を取り込む | `archive_transcripts.py claude-code --session <会話ID>`（Codexは `codex --session <ID>`） |
| 最近の分をまとめて | `archive_transcripts.py auto`（両方の3日分）。`--commit` を付けると brain に保存して送る |
| 全部 | `archive_transcripts.py claude-code --all` / `codex --all` |

- **自動で走る**＝会話の始まり（10分に1回まで）と終わり（毎回）。Claude Code・Codex 両方の SessionStart / SessionEnd フックから裏で走り、会話は待たせない。結果は `~/.cache/ai-transcripts/auto.log`
- brain へは `90_System/transcripts/` の Markdown **だけ**を保存して送る。他の変更が add 済みなら保存しない。Markdown 以外（.jsonl・.zip・.json）は `.gitignore` と道具の両方で止める
- 同じ会話は同じファイルを更新する（先頭の `session:` で探す）。中身が同じなら書かない
- 秘密情報は `tools/secret_mask.py`（transcript.py・record_hook.py と共通）で伏せる。埋め込みの画像データは省略、道具の入出力1つが5万文字を超える分は省略して「何文字省いたか」を書く
- Codex の内部指示（developer）・自動で差し込まれる AGENTS.md や環境情報・暗号化された推論は入れない（件数だけ冒頭に書く）
- work-log の `transcript:` には `90_System/transcripts/...` の形で書く。書いたパスが無いと `record_hook.py` が知らせる

work-log はこの全文ログへの索引。記事・教材を作る時は、まずwork-logで対象を絞り、必要な全文ログへ戻って判断理由・比較・失敗・途中経過を拾う。

## 6. 秘密情報

APIキー・パスワード・アクセストークン・Cookie・秘密鍵・個人情報（名前・住所・電話・メール・口座等）は**記録に書かない。**
使った事実だけ書く（例：「Civitai のトークンを使った（値は .env）」）。

- work-log の下のファイルを書くと、機械が秘密らしきものを探して知らせる（`~/ai-rules/tools/record_hook.py`）
- `transcript.py` は画面に出す時も保存する時も伏せ字にする

## 7. あとで探す

| 知りたいこと | やり方 |
|---|---|
| あの時何をした・なぜそうした | `work-log/` を日付・題で開く。決定の理由は「決定事項」 |

| Claude Codeの生ログ一覧 | `transcript.py list`（`--all` で全プロジェクト） |

## 8. プロジェクト固有の項目を足すとき

1. そのリポジトリの `AGENTS.md` に「## 作業の記録（固有の項目）」節を作る（新しいリポジトリは `~/ai-rules/TEMPLATE.md` に最初から枠がある）
2. 書くのは**この案件だけで追加で残すもの**だけ（例：段階の番号、画像生成の設定、販売の数字の取り方）。共通の欄をそこに写さない
3. 欄を足すなら work-log の頭（`---` の間）に足す（例：`段階: 2`）。後で `grep "段階:"` で並べられる
4. 固有の情報を**他のプロジェクトの記録やネタ帳に写さない**（外に出す仕組みがあるリポジトリに混ざるため）

## 10. 前後の記録（こう変えたら、こうなった）（2026-09-23 拓巳指示）

> 「コンテンツ化する前提で、失敗したやつと変わった後のとか比較できるように残しといてって言ったじゃん」
> 「画像だけじゃなくて、文章とかでも、もうすべてを記録してほしい。変わったところとか、こうやったらこうなったとか、めちゃくちゃ重要」
> 「どこでもだよ」
